# v2.3 implementation and validation notes

## Ideas from multitest

[saveksme/multitest](https://github.com/saveksme/multitest) was reviewed on
2026-09-06 as a product reference. Server Bench adds an independently written
module selector with duration estimates, a separate geoblock module and a native
Russian iPerf3 test. No multitest code or visual assets are bundled.

The CLI remains usable as a single downloaded Bash file. `--menu` accepts
numbers, comma-separated selections and ranges, then shows the selection again
before Enter starts it. Its `quick` and `all` presets match the CLI presets;
optional modules can be selected by number. `--list` works without a terminal.

## Russian throughput measurements

The five primary hostnames are listed in
[itdoginfo/russian-iperf3-servers](https://github.com/itdoginfo/russian-iperf3-servers).
Server Bench runs the installed iPerf3 client directly. It does not download or
execute that project's speedtest script.

Each destination gets an upload measurement followed by a separate `-R`
download measurement. Sender and receiver statistics from a single upload are
not two traffic directions; see the [iPerf3 manual](https://software.es.net/iperf/invoking.html).
The receiver's delivered bitrate is used for each measurement.

- Five cities: Moscow, Saint Petersburg, Nizhny Novgorod, Chelyabinsk and Tyumen.
- Four TCP streams, five seconds per direction, three-second connection timeout.
- Ports 5201–5203 are attempted until an upload succeeds. Each attempt is bounded
  by a 15-second timeout plus a two-second termination grace period.
- A failed reverse test keeps the valid upload but reports download as unavailable.
- JSON contains host, selected port, upload/download Mbps and a completed count.
- Busy or unavailable public endpoints can extend a run or leave missing values.
  The displayed duration is an estimate, not a deadline for the whole suite.

CPU, disk and throughput workloads still run sequentially. Only lightweight
ping, DNS and public IPv4/IPv6 discovery probes run concurrently.

## Behavior changes

`--no-install` and `--hide-ip` skip live external scripts because Server Bench
cannot enforce those options inside another script. Built-in RU throughput
remains available with installed tools and is also included in JSON mode.
Hostname and rDNS are hidden with `--hide-ip`; this flag does not anonymize
every other identifier in a report.

Output/control flags alone now select the normal default suite. For a short
machine-readable check, use `--json --quick` explicitly. External-only selections
in JSON mode produce skipped module statuses.

The SSH audit reports unknown settings if `sshd -T` is unavailable. It no longer
guesses effective settings by concatenating files, which mishandles Include and
Match directives. Pending apt updates describe the cached package lists.

fio results require a successful command and a zero job error field. Random
tests use `time_based` to complete their advertised sampling interval. There is
no silent switch from direct fio I/O to buffered cache throughput. The existing
dd fallback remains approximate. Format/parameter references:
[fio documentation](https://fio.readthedocs.io/en/latest/fio_doc.html#terse-output).

Reports use private, unique files named `server-bench-<timestamp>.log.<random>`.
The caller's `TMPDIR` is respected and is never repurposed as internal state.
JSON module statuses are `ok`, `warning`, `failed` and `skipped`, with per-module
elapsed seconds. Numeric measurements that could not be obtained are `null`.

## Validation

Run offline regressions and static checks:

```bash
python3 -m unittest discover -s tests -v
bash -n server-bench.sh
bash -n tests/integration.sh
shellcheck server-bench.sh tests/integration.sh
```

On Linux with fio, iperf3, jq and GNU timeout installed:

```bash
bash tests/integration.sh
```

Integration tests exercise real iPerf3 upload/reverse download on `127.0.0.1`,
fio against an 8 MiB temporary file, and termination of a fixture script's child
process. They do not run public speed tests or live external scripts. The CI
smoke job additionally validates CPU/disk measurements from the complete local
suite and checks JSON and report saving.
